# 01 — Chat Data Model & Migrations

> Prerequisite: none  
> Output: new DB tables, Rust models, TypeScript types, migration to schema version 18

---

## Goal

Replace the two separate chat storage systems (`conversation_messages` for spec brainstorming and `validation_sessions` + `validation_messages` for validation) with a unified chat data model that supports four modes: General, Spec Builder, Ticket Builder, and Review.

---

## New Tables

### `chats`

Top-level entity representing a chat session. Each chat has a mode, an associated agent and project, and optional relationships depending on mode.

```sql
CREATE TABLE IF NOT EXISTS chats (
    id TEXT PRIMARY KEY NOT NULL,
    title TEXT,  -- generated by agent on first message, NULL until generated
    agent_type TEXT NOT NULL,  -- 'claude', 'cursor', 'codex'
    project_id TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
    mode TEXT NOT NULL CHECK(mode IN ('general', 'spec_builder', 'ticket_builder', 'review')),

    -- Mode-specific foreign keys (nullable)
    board_id TEXT REFERENCES boards(id) ON DELETE SET NULL,       -- required for ticket_builder, review
    ticket_id TEXT REFERENCES tickets(id) ON DELETE SET NULL,     -- required for review
    spec_id TEXT REFERENCES specs(id) ON DELETE SET NULL,         -- set for spec_builder

    -- Model override tracking
    model TEXT,  -- resolved model override at chat creation time

    status TEXT NOT NULL DEFAULT 'active' CHECK(status IN ('active', 'thinking', 'completed', 'error')),
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE INDEX IF NOT EXISTS idx_chats_project ON chats(project_id);
CREATE INDEX IF NOT EXISTS idx_chats_mode ON chats(mode);
CREATE INDEX IF NOT EXISTS idx_chats_board ON chats(board_id) WHERE board_id IS NOT NULL;
CREATE INDEX IF NOT EXISTS idx_chats_ticket ON chats(ticket_id) WHERE ticket_id IS NOT NULL;
CREATE INDEX IF NOT EXISTS idx_chats_spec ON chats(spec_id) WHERE spec_id IS NOT NULL;
CREATE INDEX IF NOT EXISTS idx_chats_created ON chats(created_at);
```

### `chat_messages`

Messages within a chat session. Replaces both `conversation_messages` and `validation_messages`.

```sql
CREATE TABLE IF NOT EXISTS chat_messages (
    id TEXT PRIMARY KEY NOT NULL,
    chat_id TEXT NOT NULL REFERENCES chats(id) ON DELETE CASCADE,
    role TEXT NOT NULL CHECK(role IN ('user', 'assistant', 'system')),
    content TEXT NOT NULL,
    metadata_json TEXT,  -- per-message metadata (fix tasks, structured spec output, cost data, etc.)
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE INDEX IF NOT EXISTS idx_chat_messages_chat ON chat_messages(chat_id);
CREATE INDEX IF NOT EXISTS idx_chat_messages_created ON chat_messages(chat_id, created_at);
```

### `chat_events`

Raw agent timeline events for a chat turn. Stored so they can be replayed in the timeline view after the turn completes.

```sql
CREATE TABLE IF NOT EXISTS chat_events (
    id TEXT PRIMARY KEY NOT NULL,
    chat_id TEXT NOT NULL REFERENCES chats(id) ON DELETE CASCADE,
    message_id TEXT REFERENCES chat_messages(id) ON DELETE CASCADE,  -- the assistant message this event belongs to
    event_type TEXT NOT NULL,  -- 'log_stdout', 'log_stderr', 'agent_complete', etc.
    payload_json TEXT NOT NULL DEFAULT '{}',
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE INDEX IF NOT EXISTS idx_chat_events_chat ON chat_events(chat_id);
CREATE INDEX IF NOT EXISTS idx_chat_events_message ON chat_events(message_id) WHERE message_id IS NOT NULL;
```

### `chat_runs`

One record per agent invocation (turn) in a chat. Stores cost data using the same `RunCostData` schema as `agent_runs.metadata_json`. This table is the foundation for per-chat cost aggregation.

```sql
CREATE TABLE IF NOT EXISTS chat_runs (
    id TEXT PRIMARY KEY NOT NULL,
    chat_id TEXT NOT NULL REFERENCES chats(id) ON DELETE CASCADE,
    chat_message_id TEXT REFERENCES chat_messages(id) ON DELETE SET NULL,  -- the assistant response message
    agent_type TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'running' CHECK(status IN ('running', 'finished', 'error')),
    metadata_json TEXT,  -- stores RunCostData under "cost" key, agent_config, duration_secs — same schema as agent_runs
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE INDEX IF NOT EXISTS idx_chat_runs_chat ON chat_runs(chat_id);
CREATE INDEX IF NOT EXISTS idx_chat_runs_message ON chat_runs(chat_message_id) WHERE chat_message_id IS NOT NULL;
```

## Migration (Schema Version 18)

```rust
if current_version < 18 {
    conn.execute_batch(r#"
        CREATE TABLE IF NOT EXISTS chats ( ... );
        -- all indexes
        CREATE TABLE IF NOT EXISTS chat_messages ( ... );
        -- all indexes
        CREATE TABLE IF NOT EXISTS chat_events ( ... );
        -- all indexes
        CREATE TABLE IF NOT EXISTS chat_runs ( ... );
        -- all indexes

    conn.execute("INSERT INTO schema_version (version) VALUES (18)", [])?;

```

The existing `conversation_messages`, `validation_sessions`, and `validation_messages` tables are **not dropped** in this migration. They remain for backward compatibility and will be referenced during data migration (spec 08 and 10). They can be dropped in a future migration after the refactor is validated.

## DB Query Module

Create `src-tauri/src/db/chats.rs` with CRUD operations following patterns from `src-tauri/src/db/conversations.rs` and `src-tauri/src/db/validation_sessions.rs`:

- `create_chat(input: &CreateChat) -> Result<Chat, DbError>`
- `get_chat(id: &str) -> Result<Chat, DbError>`
- `get_chats(limit: i64, offset: i64) -> Result<Vec<Chat>, DbError>` — ordered by `created_at DESC`
- `update_chat_title(id: &str, title: &str) -> Result<(), DbError>`
- `update_chat_status(id: &str, status: ChatStatus) -> Result<(), DbError>`
- `delete_chat(id: &str) -> Result<(), DbError>`
- `create_chat_message(chat_id: &str, role: ChatMessageRole, content: &str, metadata: Option<&serde_json::Value>) -> Result<ChatMessage, DbError>`
- `get_chat_messages(chat_id: &str) -> Result<Vec<ChatMessage>, DbError>`
- `create_chat_event(chat_id: &str, message_id: Option<&str>, event_type: &str, payload: &serde_json::Value) -> Result<(), DbError>`
- `get_chat_events(chat_id: &str) -> Result<Vec<ChatEvent>, DbError>`
- `create_chat_run(chat_id: &str, chat_message_id: Option<&str>, agent_type: &str) -> Result<ChatRun, DbError>`
- `update_chat_run_status(id: &str, status: ChatRunStatus) -> Result<(), DbError>`
- `set_chat_run_metadata(id: &str, metadata: &serde_json::Value) -> Result<(), DbError>`

### Cost Aggregation

Add to `src-tauri/src/db/costs.rs`:

```rust
pub fn get_chat_cost(&self, chat_id: &str) -> Result<AggregatedCost, DbError> {
    self.aggregate_cost_by_query(
        r#"SELECT metadata_json FROM chat_runs
           WHERE chat_id = ? AND metadata_json IS NOT NULL"#,
        chat_id,
    )
}
```

This reuses the existing `aggregate_cost_by_query` and `aggregate_metadata_rows` infrastructure. No parent/sub-run exclusion logic needed because `chat_runs` has no hierarchy — each record is a single agent invocation.

## Mode-Specific Validation

When creating a chat, validate that required fields are present for the mode:

| Mode | Required fields |
|------|----------------|
| `general` | `agent_type`, `project_id` |
| `spec_builder` | `agent_type`, `project_id` |
| `ticket_builder` | `agent_type`, `project_id`, `board_id` |
| `review` | `agent_type`, `project_id`, `board_id`, `ticket_id` |

This validation should be enforced in the `create_chat` DB function and/or the Tauri command (spec 03).

## Backward Compatibility

- The `conversation_messages` table continues to exist and be queryable. Existing spec conversations are **not** migrated automatically — this is handled in spec 08.
- The `validation_sessions` and `validation_messages` tables continue to exist. Existing validation data is **not** migrated — this is handled in spec 10.
- No existing code is modified in this spec. The new tables and models are additive.
